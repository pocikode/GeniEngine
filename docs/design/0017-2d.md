# 0017: 2D sprites, tilemaps and physics

Milestone: M7 (moved forward from "After v0.1") · Status: Done · Last updated: 2026-11-12

## Problem

Everything the engine draws is a mesh with a PBR material. A 2D game (a platformer, a
top-down game) needs textured, alpha-blended quads in a set order, sprite-sheet
animation, tile maps that hold hundreds of thousands of tiles, an orthographic camera,
colours that reach the screen exactly as painted, and physics in a plane. The game UI
(docs/design/0015) draws screen-space panels and text only, through Dear ImGui.

**Done** means a 2D platformer (`samples/platformer`) is built from a scene file edited in
the editor, with a tilemap that collides, an animated player on the character controller,
falling crates, collectable coins and parallax layers; it has a screenshot test, a scripted
play-through and a sprite benchmark.

## Approach

**Sprites are drawn by the renderer inside the HDR scene pass, after the opaque meshes,
with the same camera.** One camera model serves 2D, 2.5D and 3D; the editor's viewport,
picking and play mode work unchanged, and sprites in a 3D world are occluded by it.

- **Camera**: `CameraComponent` gets `projection` (`perspective` / `orthographic`) and
  `orthoSize` (the visible height in world units). 2D content lies in the XY plane, with
  +Y up and the camera looking down −Z.
- **Submission**: `RenderQueue::SubmitSprites(SpriteCommand)`: a texture (null: white),
  a filter (linear or nearest), a span of `SpriteQuad`s in the object's space (rectangle,
  UV rectangle, linear colour), the model matrix, local bounds and a sort `layer`. The
  quads belong to the component and live until the frame is drawn.
- **Drawing**: the renderer culls each command by its bounds, sorts by layer, then back to
  front along the view direction, then by submission order, writes camera-relative
  vertices (position, UV, colour, sRGB flag) into a per-frame buffer and draws runs that
  share a texture and filter with one indexed draw. The pipeline blends alpha, tests depth
  and does not write it. The texture and sampler bind group is cached per texture.
  `RenderStats` gets `sprites`, `spriteBatches`.
- **Colour**: textures are decoded to linear (cooked sRGB formats by the sampler, other
  textures in the shader) and multiplied by the tint, which is given in sRGB.
  `RendererConfig::tonemapper = Tonemapper::None` replaces the ACES curve with a clamp,
  and `sky = false` with `clearColor` (sRGB) replaces the sky, so with exposure 1 a sprite's
  pixels reach the screen unchanged (within one level).
- **Components** (reflected, so the scene format, inspector and Lua see them):
  - `SpriteComponent`: texture, size in world units, pivot, tint, atlas grid
    (`columns`, `rows`) and `frame`, `flipX`/`flipY`, `layer`, `filter`.
  - `SpriteAnimatorComponent`: plays `frameCount` frames from `firstFrame` of the sprite
    on the same object at `fps`, looping or not; `Play(first, count, fps, loop)`.
  - `TilemapComponent`: a tileset texture cut into `columns` × `rows` tiles, a map of
    `width` × `height` cells of `tileSize`, the tiles as text (comma-separated tile indices,
    −1 for empty, rows from the top; the object's origin is the map's top-left corner).
    It builds its quads in 16 × 16-cell chunks, each its own `SpriteCommand`, so off-screen
    chunks are culled. With `collision` on, the tiles listed in `solidTiles` become static
    box bodies, horizontal runs merged into one box, rebuilt when a tile changes.
    `GetTile`, `SetTile`, `WorldToCell`, `CellToWorld`.
- **Physics in a plane**: `PhysicsComponent::plane2D` creates dynamic bodies with Jolt's
  `EAllowedDOFs::Plane2D` (move in X and Y, rotate about Z). The existing
  `CharacterControllerComponent` serves as the 2D player: its move input is given along X.
- **Cooker**: a `.meta` `"usage": "sprite"` cooks an image as RGBA8 sRGB with one mip
  level and no BC/ASTC variants, so pixel art stays exact.
- **Lua**: the reflected properties (`sprite.frame`, `sprite.flipX`, ...) plus methods on
  sprite animators (`play`, `stop`, `finished`) and tilemaps (`tile`, `set_tile`, `solid`,
  `cell_at`, `cell_center`); see docs/scripting.md.

## Rejected

- **A separate 2D pass in the backbuffer after tonemapping.** Exact colours for free, but
  a second camera model, no occlusion by 3D, and the editor would need a 2D view mode.
- **Drawing sprites through the game UI's ImGui draw lists.** Screen-space only, no
  camera, no depth, no batching control.
- **Sprites as meshes with an unlit material.** One draw per sprite and a material per
  frame of animation; a 10,000-sprite scene would be 10,000 draws.
- **Box2D.** A second physics engine with its own bodies, queries and character code;
  Jolt in a plane covers platformers and top-down games.
- **Tiled (`.tmx`) import now.** The tile text format is close to Tiled's CSV layer, so an
  importer in the cooker is a small step once someone asks.

## To verify

- Done: 10,000 moving, animated sprites at 8.6 ms per frame on an Apple M4 (release,
  1280x720, 8 draw batches; `platformer --benchmark 10000`). Still to measure on a mid-range
  Windows GPU and the Steam Deck.
- Clustered lighting with an orthographic camera: lights are not used by sprites, but a
  lit mesh under an orthographic camera is only roughly clustered. Default: documented
  limit.
